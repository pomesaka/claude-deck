# ADR-016: 表示用のエイリアスを持ち、トークンの集計をやめる

## ステータス

Accepted（2026-10-10）

## コンテキスト

一覧の各行は、作業ディレクトリとセッション名（`shoko-677b` のような自動生成の名前）、トークン数、コストを出していた。

- セッションが増えると、自動生成の名前では何をしているセッションかが分からない
- トークン数とコストは、一覧で見ても判断に使わない。一方で TUI は、この表示のために 5 秒ごとに全セッションの JSONL を読んでいた

## 決定

### エイリアス

1. store に `alias` の列を持ち、`claude-deck alias [--session ID|NAME] <ALIAS>` で書く。`--session` を省くと自分のセッション（`$CLAUDE_DECK_SESSION_ID`）なので、Claude Code が自分のセッションに名前を付けられる
2. 一覧は、エイリアスがあればそれを出し、無ければセッション名を出す
3. 使えるのは ASCII の英数字と `-` `_` `.` で、40 文字まで。一覧の桁そろえと切り詰めは 1 文字 1 桁の前提で、全角文字が入ると行が崩れる
4. エイリアスは表示だけに使う。セッション名は変えない

### 一覧の表示

1 行目に状態・作業ディレクトリ・jj のブックマーク、2 行目に開始と最終更新の日時・名前を出す。トークン数とコストは出さない。

### トークンの集計

`HydrateFromJSONL`、`usage.Reader.ReadTokensByID`、`TokenUsage`、`[pricing]` の設定を削除する。store の 5 列（`input_tokens` など）は `schema` と `columns` から外す。既存の DB の列は消さない（書き込みは列を名指しするので、残っていても既定値が入るだけ）。

## 結果

### 良い点

- 一覧で、何をしているセッションかが分かる
- 5 秒ごとの JSONL の読み取りが無くなる

### 悪い点

- エイリアスと、セッション間メッセージの宛先（`@名前`）が一致しない。宛先と `close` の指定には、今までどおりセッション名を使う

### 却下した代替案

- **セッション名そのものを変える**: セッション名は jj ワークスペースの名前とディレクトリ名を兼ねる。再開はこの名前でワークスペースを作り直し、`gc` はこの名前のワークスペースを持ち主ありと判定する。途中で変えると、動いているセッションのワークスペースが持ち主なしに見える
- **エイリアスを Claude Code のセッション名（`/rename`）と同期する**: `/rename` で宛先名が即時に変わることは確かめた（Claude Code 2.1.296）。ただし `claude-deck alias` から Claude Code 側を改名するには、tmux でキー入力を送るか、相手のプラグインが次に動くのを待つしかない。前者は入力欄の書きかけを壊し、後者は即時に反映されない
- **コストを Mods の `session.measure` から取って出す**: 取れるが、一覧で見る用途が無いので持たない。必要になったら、JSONL を読み直さずにここから取れる
