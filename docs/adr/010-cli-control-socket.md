# ADR-010: CLI サブコマンドは起動中の TUI に Unix ソケットで依頼する

## ステータス

Accepted

## コンテキスト

Claude Code のセッション（PM 役）がスキル経由で別のセッションを立ち上げ、cross session message で仕事を配れるようにしたい。そのため TUI の `n`（新規作成）と `x`（終了）、一覧の取得をコマンドラインから実行できる必要がある。立ち上がるセッションは PM の子ではなく、TUI で作ったものと同じ独立したセッションとして扱う。

セッションの実行状態（tmux ウィンドウとの対応・終了監視の goroutine）は TUI プロセスの `Manager` がメモリに持っている。

## 決定

`claude-deck new / list / close` は、TUI プロセスが `{DataDir}/control.sock` で待ち受ける Unix ソケットへ JSON の要求を 1 つ送り、応答を 1 つ受け取る。TUI 側は `control.ManagerHandler` が `Manager.Launch`（`n` と同じ）と `Manager.Kill`（`x` と同じ）を呼ぶ。

- `new` の `--dir` が jj ワークスペース内なら、本体リポジトリの同じ相対位置に解決する（`session.ResolveLaunchDir`）。PM は自分のワークスペースから呼ぶことが多いため
- `close` の対象は deck セッション ID か名前。名前が複数のセッションに一致したら推測せずエラーにする
- ソケットは所有者だけが接続できるよう 0600 にする。接続できる人はセッションを起動・終了できるため
- TUI が起動していなければ CLI はエラーで終わる

## 結果

**良い点**
- CLI から作ったセッションも `n` と同じ経路を通るので、終了監視を含めて TUI で作ったものと区別がない
- store に書くのは TUI プロセスだけのままで、プロセス間の書き込み競合が生じない
- `new` が作ったセッションの名前を同期で返せるので、PM はその名前で cross session message を送れる

**悪い点**
- TUI が起動していないと使えない
- TUI の `x` には二重実行を防ぐ `killing` フラグ（ADR-008）があるが、CLI の `close` はそれを通らない。同じセッションを TUI と CLI で同時に終了すると、両方が同じワークスペースの削除を試みる

**却下した代替案**
- CLI が自分で `Manager` を作ってセッションを起動する案。TUI は store の 5 秒 tick（`SyncNewFromStore`）で一覧には追従するが、終了監視は起動したプロセスにしか付かない。store の書き手も 2 プロセスになる
- store を SQLite に移してトランザクションで守る案。書き手が TUI だけになれば競合は起きないので、今は不要
- preview と同じファイル経由の IPC。`new` は作ったセッションの名前を返す必要があり、要求と応答を対にできるソケットの方が単純になる
