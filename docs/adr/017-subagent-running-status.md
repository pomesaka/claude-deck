# ADR-017: サブエージェントだけが動いている状態を表すステータス

## ステータス

採用（2026-10-10）

## コンテキスト

メインのターンが終わると、deck-status プラグインはステータスを `idle` にしていた。バックグラウンドで起動したサブエージェントは、メインのターンが終わった後も動き続ける。一覧では、作業が続いているセッションと、利用者の入力を待っているセッションの見分けが付かなかった。

## 決定

ステータス `subagent_running`（`StatusSubagentRunning`）を足す。メインのターンは終わっていて、サブエージェントが動いている状態を表す。一覧では青の丸で出す（`[theme] status_subagent`）。並び順は Running と同じ組にする。

判定はプラグインが行う。

- メインの `turn.complete` で `$.agent.list()` を読み、`pending` / `running` / `waiting` のエージェントがあれば `subagent_running`、無ければ `idle` を書く
- サブエージェントの `turn.complete`（`agentId` あり）で、直前が `subagent_running` なら同じ判定をやり直す

Claude Code 2.1.296 で、次のことを確かめた。

- メインの `turn.complete` の時点で、バックグラウンドのサブエージェントは一覧に `running` で出る
- サブエージェントの `turn.complete` の時点で、そのエージェントは一覧で `completed` になっている
- サブエージェントが動いている間にメインが別の通知で起きてターンを終えると、`subagent_running` に戻る

## 結果

**良い点:**
- 作業が続いているセッションを、入力待ちのセッションと見分けられる
- プラグインは数を持たない。Mod が読み込み直されても、次の `turn.complete` で正しい状態になる

**悪い点:**
- ワークフローのエージェントは `$.agent.list()` に出ないので、ワークフローだけが動いている間は `idle` になる（型定義 `AgentLoop.agentId` の説明。動作は未確認）
- バックグラウンドのシェルやモニターは数えない
- このステータスを知らない版の TUI は、行のステータスを読み直せず、直前の表示のままになる

**却下した代替案:**
- `agent.spawn` と `turn.complete` で数える: Mod の読み込み直しで数が失われ、終了を 1 つ取りこぼすと表示が残り続ける
- `classic.Stop` の `background_tasks` を使う: シェルやワークフローも入るが、サブエージェントが終わった時点（メインは止まったまま）で読み直す手段が無い
